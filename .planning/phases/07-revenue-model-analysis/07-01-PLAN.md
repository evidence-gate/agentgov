Conduct web research on revenue models for AI infrastructure and developer tools, then write the first part of the report section. Include:

1. **Introduction (## 7.1)**: Why revenue model selection is critical for small-team AI infrastructure startups. Reference Phase 5 (market sizing) and Phase 6 (entry barriers) findings.

2. **Revenue Model Pattern Catalog (## 7.2-7.6)**: Document each major pattern with:

   **Pattern 1: API Usage-Based Pricing (## 7.2)**
   - Model: Pay per API call, token, or event processed
   - Real examples: Portkey (% of managed LLM spend), E2B ($0.067/hr), OpenAI API pricing
   - Pros: Aligns cost with value, low entry barrier for customers, scales naturally
   - Cons: Revenue unpredictability, requires volume, race-to-bottom risk
   - Suitability for Cost Control / HITL / Error Handling

   **Pattern 2: SaaS Subscription (## 7.3)**
   - Model: Fixed monthly/annual tiers (Free/Pro/Enterprise)
   - Real examples: Braintrust ($0-custom), Lakera (per-request + tiers), Patronus AI
   - Pros: Predictable revenue, easier planning, higher LTV
   - Cons: Feature gating complexity, slower initial adoption
   - Suitability for Cost Control / HITL / Error Handling

   **Pattern 3: OSS Core + Cloud Monetization (## 7.4)**
   - Model: Open-source self-hosted + paid cloud hosting + enterprise features
   - Real examples: Langfuse, PostHog, Supabase, GitLab, Grafana
   - Pros: Maximum adoption, community moat, acquisition currency
   - Cons: Delayed monetization, self-host cannibalization risk
   - Suitability for Cost Control / HITL / Error Handling

   **Pattern 4: Marketplace / Platform Fee (## 7.5)**
   - Model: Take rate on transactions between agents/services
   - Real examples: Composio, MCP marketplace concepts, Cloudflare Workers marketplace
   - Pros: Network effects, high margins at scale
   - Cons: Chicken-and-egg problem, requires ecosystem
   - Suitability: Low for recommended categories (requires platform scale)

   **Pattern 5: Hybrid Models (## 7.6)**
   - Model: Combinations of above patterns
   - Real examples: Datadog (usage + subscription), Vercel (freemium + usage), Stripe (% + subscription)
   - Why hybrid is the realistic path for most AI infrastructure products
   - Recommended hybrid for "Agent Governance" platform

3. **Revenue Model Comparison Matrix (## 7.7)**: Summary table comparing all patterns across: time-to-first-dollar, revenue predictability, scalability, small-team fit, alignment with Cost Control/HITL categories.

Write in Japanese with English technical terms preserved. Start with section header (# 7. 収益モデル分析).
