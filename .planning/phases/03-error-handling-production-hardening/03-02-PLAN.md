<objective>
Stuck/loop detector for agents that repeat the same action with identical inputs.

Purpose: Agents stuck in loops waste budget and time. The 2-failure-stop rule detects repeated tool_calls before forwarding to the LLM, stopping the agent with a diagnostic error. Per-request in-memory state (no DB needed).

Output: `error/loop-detector.ts` module; integration into proxy pipeline; test coverage.
</objective>

    1. **Create `packages/proxy/src/error/loop-detector.ts`**:
       - `ActionRecord` interface: `{ fingerprint: string, timestamps: number[], count: number }`
       - `LoopDetectorState` interface: `{ history: Map<string, ActionRecord> }`
       - `createLoopDetector(): LoopDetectorState` — returns `{ history: new Map() }`
       - `fingerprintAction(actionName: string, argsJson: string): Promise<string>`:
         - Parse argsJson to object, then re-serialize with `JSON.stringify({ action: actionName, args: parsed }, sortKeysReplacer)` for deterministic ordering.
         - Hash with `crypto.subtle.digest('SHA-256', encoded)` — same API used in `audit/writer.ts`.
         - Return lowercase hex string (64 chars).
         - If argsJson parse fails, use the raw string (non-JSON arguments should still fingerprint consistently).
       - `sortKeysReplacer(_key: string, value: unknown): unknown` — if value is non-array object, sort entries and return `Object.fromEntries`.
       - `StuckResult` discriminated union:
         - `{ stuck: false }` or
         - `{ stuck: true, repeatedFingerprint: string, actionName: string, timestamps: number[], suggestedRemediation: string }`
       - `recordAction(state: LoopDetectorState, fingerprint: string, actionName: string, now: number): StuckResult`:
         - If fingerprint not in history: add it, return `{ stuck: false }`.
         - If fingerprint exists: increment count, push timestamp.
         - If count >= 2: return stuck result with remediation message:
           `"Agent repeated action '${actionName}' ${count} times with identical inputs. Check for missing state updates or broken feedback loops in agent logic."`
         - Otherwise: return `{ stuck: false }`.

    1. **Modify `packages/proxy/src/index.ts`** — add loop detection step:

       - Import `createLoopDetector`, `fingerprintAction`, `recordAction` from `./error/loop-detector`.
       - Import `buildAgentErrorResponse` from `./error/reporter`.
       - Import `appendAuditEvent` from `./audit/writer`.

       - **Insert Step 4.75** (after HITL check in Step 4.5, before forwardToLlm in Step 5):
         "Step 4.75: Stuck/loop detection — check if incoming request contains repeated identical tool_calls."

       - Logic (per-request scope per CONTEXT.md discretion):
         ```
         const loopState = createLoopDetector();
         // Scan ALL messages in the request for tool_calls
         for (const message of body.messages) {
           if (!message.tool_calls) continue;
           for (const tc of message.tool_calls) {
             const fp = await fingerprintAction(tc.function.name, tc.function.arguments);
             const result = recordAction(loopState, fp, tc.function.name, Date.now());
             if (result.stuck) {
               // Log to audit
               await appendAuditEvent(db, {
                 eventType: 'stuck_detected',
                 agentId,
                 model: body.model,
                 costDelta: 0,
                 runningBalance: 0,
                 meta: {
                   repeatedAction: result.actionName,
                   timestamps: result.timestamps,
                   fingerprint: result.repeatedFingerprint,
                   suggestedRemediation: result.suggestedRemediation,
                 },
               });
               // Settle hold at 0 cost (no LLM tokens consumed — halted before forward)
               await budgetSettle(db, holdId, { promptTokens: 0, completionTokens: 0 }, body.model, agentId);
               // Return structured error
               return buildAgentErrorResponse(
                 'stuck_detected',
                 agentId,
                 { suggestedRemediation: result.suggestedRemediation },
               );
             }
           }
         }
         ```

       - This runs BEFORE `forwardToLlm` — if stuck is detected, the request never reaches the LLM, saving budget.

       - Import `budgetSettle` from `./budget/gate` (already imported indirectly via `forwardToLlm`, but now needed directly in index.ts for the stuck halt path).

       - Use the same mocking pattern as existing index.test.ts tests (mock DB client, budgetGate, forwardToLlm).

    IMPORTANT: Loop detection checks incoming request messages for repeated tool_calls (what the agent sent), NOT the LLM response tool_calls. This is simpler and avoids SSE parsing. An agent in a loop will send the same tool_call across successive request messages.
