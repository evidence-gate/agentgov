export function createDbClient(url: string, authToken: string) {

    1. **client.node.ts**: Create a Node.js-specific DB client factory. Import from `@libsql/client` (bare, NOT `/web`). Accept a `url` parameter (default `process.env.DATABASE_URL ?? 'file:agentgov.db'`). No `authToken` needed for `file:` URLs. Return `drizzle(client, { schema })`. Also export a `runMigrations(db)` function that calls `migrate(db, { migrationsFolder: './migrations' })` from `drizzle-orm/libsql/migrator`. This is idempotent and runs on container startup.

    2. **dashboard/routes.ts**: Create a Hono router with three read-only GET endpoints:
       - `GET /api/v1/dashboard/budgets` — `SELECT * FROM budget_ledger` -> JSON array
       - `GET /api/v1/dashboard/audit` — `SELECT * FROM audit_log ORDER BY seq DESC LIMIT ?` (query param `limit`, default 100) -> JSON array
       - `GET /api/v1/dashboard/approvals` — `SELECT * FROM hitl_queue WHERE status = 'pending' ORDER BY created_at DESC` -> JSON array

       The router needs DB access. Since the Docker entry point creates its own DB client, pass it via Hono context variable (c.set/c.get pattern) or via a middleware that sets `c.var.db`. For simplicity, the dashboard routes can accept a db instance injected via a factory function: `export function createDashboardRoutes(db: DbClient)` that returns a Hono app with the routes. This avoids coupling to Cloudflare's env binding pattern.

       IMPORTANT: These endpoints are SELECT-only. No POST/PUT/DELETE. This is a hard constraint.

    3. **package.json**: Add `@hono/node-server` and `@libsql/client` to dependencies (the bare import, alongside the existing `/web` usage for Workers). Add `tsx` to devDependencies for running TypeScript directly in Docker. Add a script: `"start:node": "tsx src/index.node.ts"`.

       Install: `cd packages/proxy && pnpm add @hono/node-server @libsql/client && pnpm add -D tsx`

       NOTE: `@libsql/client` may already be a transitive dependency. The bare import is needed for Node.js native SQLite bindings. The `/web` sub-path import in `client.ts` remains unchanged for Workers.

       - CRITICAL: The existing `app` references `c.env.TURSO_DATABASE_URL` etc. For Docker, these come from `process.env`. Create a Hono middleware that maps `process.env` values into `c.env` so the existing proxy code works unchanged: `app.use('*', async (c, next) => { c.env = { ...c.env, TURSO_DATABASE_URL: process.env.DATABASE_URL, TURSO_AUTH_TOKEN: 'local', OPENAI_API_KEY: process.env.OPENAI_API_KEY, ANTHROPIC_API_KEY: process.env.ANTHROPIC_API_KEY, ...otherEnvVars }; await next(); })`
       - CRITICAL: Guard HITL Workflow calls. The existing `app` calls `c.env.HITL_WORKFLOW.create(...)`. In Node.js, this binding doesn't exist. Add an early middleware that stubs `c.env.HITL_WORKFLOW` to undefined (if not already). The existing code in index.ts will need a guard: if `c.env.HITL_WORKFLOW` is falsy, return 501 with `{ error: { code: 'HITL_NOT_AVAILABLE', message: 'HITL requires Cloudflare Workflows deployment' } }`. Add this guard in index.node.ts as a route override BEFORE mounting the main app, or patch the env to include a stub.
       - Calls `serve({ fetch: app.fetch, port: parseInt(process.env.PORT ?? '8787') })`
       - NOTE: Do NOT import from `@libsql/client/web` in this file. Use `./db/client.node` only.

    2. **docker/Dockerfile.proxy**: Multi-stage build:
       ```
       FROM node:20-alpine AS builder
       WORKDIR /app
       RUN npm install -g pnpm
       COPY package.json pnpm-workspace.yaml pnpm-lock.yaml ./
       COPY packages/proxy/package.json ./packages/proxy/
       RUN pnpm install --frozen-lockfile
       COPY packages/proxy ./packages/proxy
       # Copy migrations for runtime migrate()
       COPY packages/proxy/migrations ./packages/proxy/migrations

       FROM node:20-alpine AS runtime
       WORKDIR /app
       COPY --from=builder /app /app
       WORKDIR /app/packages/proxy
       EXPOSE 8787
       CMD ["npx", "tsx", "src/index.node.ts"]
       ```
       Use `tsx` to run TypeScript directly (no separate tsc compile step needed). This is simpler and matches the `start:node` script.
